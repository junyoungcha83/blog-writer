# 블로그작성

기사 링크·원문·주제 하나를 넣고 옵션을 고르면 **역할별 Agent 6단계**가 순서대로 돌아
블로그에 붙여넣을 원고와 SEO 세트, 썸네일 문구까지 만들어 주는 PWA.
백엔드 없이 브라우저에서 Claude API를 직접 호출한다.

```
① Researcher     검색 키워드 생성 → 자료 수집          (web_fetch + web_search)
② Fact Checker   출처 대조 → 사실 / 해석 / 미확인 분리  (web_search 보강)
③ Analyst        논리 구성 → 시각자료 필요 판단         (도구 없음)
④ Visualization  표·그래프 데이터 생성                 (도구 없음 · 필요 없으면 생략)
⑤ Writer         제목·목차·본문 작성 + 각주 + 차트 배치 (도구 없음)
⑥ SEO            제목 5안·키워드·태그·FAQ·썸네일 문구   (도구 없음)
```

④는 ③이 시각자료를 요청하지 않으면 **호출 자체를 건너뜁니다**(요금 미발생). 그래서 보통 5회,
그래프가 붙는 글은 6회 호출됩니다.

## 구조

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 뼈대(새 글·결과·이력·정보 탭 + 설정 시트) |
| `assets/agents.js` | 6개 역할의 시스템 프롬프트, 옵션 목록, 단계 정의 |
| `assets/app.js` | Claude API 호출, 파이프라인 실행, 마크다운·SVG 차트 렌더, 결과 화면 |
| `assets/app.css` | 스타일 (브리핑앱·기사검색앱과 같은 팔레트) |
| `sw.js` | 앱 셸 오프라인 캐시 — API 호출은 가로채지 않음 |

정적 파일뿐이라 GitHub Pages에 그대로 올라간다. 빌드 단계 없음.

## 입력과 옵션

입력은 세 가지 중 하나를 고른다.

- **기사 링크** — `web_fetch` 로 본문을 읽고 같은 사안의 다른 출처를 찾는다
- **원문 붙여넣기** — 붙여넣은 내용을 기준으로 사실을 확인하고 뒷받침 자료를 찾는다
- **주제만** — 검색 키워드부터 만들어 자료를 모은다

| 옵션 | 값 | 실제로 어디에 반영되나 |
|---|---|---|
| 분야 | 부동산 / 주식 / 경제 / IT / 기타 | 분야별 **신뢰 출처 목록**을 ①②에 주입 |
| 글의 목적 | 정보 제공 / 투자 분석 / 뉴스 분석 / 검색 유입 | ③④의 분석 방향 + ⑤의 구성·어조 지시 |
| 분량 | 1,500 / 3,000 / 5,000자 | ⑤의 글자 수·소제목 수 + `max_tokens` |
| 검색 범위 | 24시간 / 3일 / 7일 / 1개월 | ①에 지시 + **②에서 발행일로 실제 필터** |
| 출처 | 언론사 / 정부기관 / 공공기관 / 증권사 / 전문가 (다중) | ①의 우선순위 + ②가 유형별 확보량 집계 |
| 문체 | 전문형 / 쉬운 설명형 / 뉴스형 / 투자자 분석형 | ⑤의 문체 지시 (구성·설명 방식) |
| 말투 | 습니다체 / 해요체 | ⑤의 문장 어미 지시 + ⑥의 메타설명·FAQ 어미 |

## 동작 방식

- 단계마다 결과 JSON을 이 기기에 저장한다. 그래서 마음에 안 드는 단계만
  **이 단계부터 다시**로 다시 돌릴 수 있고, **앞 단계 요금은 다시 나가지 않는다**.
  (⑤만 재실행하면 Writer → SEO 두 번만 호출된다.)
- ②에서 검색 범위 안의 자료가 3개 미만이면 파이프라인을 멈추고 계속할지 물어본다.
  억지로 채우지 않는 게 기본이다.
- 새로고침으로 끊긴 단계는 다음 실행 때 '중간에 끊겼어요'로 표시되고 그 단계부터 재실행할 수 있다.

## 결과물

- 제목 후보 3개 중 선택 → 마크다운 미리보기
- **본문 중간에 그래프·표** (꺾은선·막대·원·표). 라이브러리 없이 SVG로 직접 그림
- 그래프마다 **PNG 저장** — 네이버·티스토리는 이미지로 올리는 게 가장 확실합니다
- 복사 3종: **마크다운 / HTML / 평문**(네이버·티스토리 에디터 붙여넣기용), `.md` 다운로드
  · 마크다운·평문에는 그래프가 **데이터 표**로 바뀌어 들어갑니다 (에디터가 SVG를 못 받는 경우가 많음)
  · HTML에는 그래프가 인라인 SVG로 들어갑니다 (워드프레스 등)
- **분석 패널**: 핵심 정리 · 엇갈리는 관점 · 주의할 점 · 전망(발언 주체 표기) · 만들지 않은 시각자료와 그 이유
- **근거 현황**: 확인된 사실·교차확인 수, 쟁점, 의견, 미확인, 검색범위 밖 제외 건수,
  요청한 출처 유형별 실제 확보량
- SEO: 제목 5안 · 메타설명 · 핵심/연관 키워드 · 태그 · FAQ · **썸네일 문구 3세트**

## 알아 둘 한계

- **웹검색은 출처와 날짜를 강제하는 기능이 없다.** 출처·검색범위 옵션은 "우선순위 지시 +
  결과 사후 검증"이라서 요청과 다를 수 있다. 실제 확보량은 결과 탭의 **근거 현황**에
  숨기지 않고 그대로 표시한다.
- **게시 전 사람 검토는 필수다.** 수치·날짜·출처는 프롬프트에서 강하게 통제하지만
  최종 책임은 사람에게 있다. 부동산·주식 분야는 투자 판단 면책 문구가 자동으로 붙는다.
- **블로그 자동 게시는 넣지 않았다.** 티스토리 Open API는 2024년 2월 종료됐고,
  네이버는 공식 글쓰기 API를 제공하지 않는다(검색 API만 있음). 복사 버튼으로
  에디터에 붙여넣는 방식이 가장 안전하다.
- 원문 인용은 문단당 2문장까지로 제한하고 나머지는 재작성하도록 프롬프트에 못박아 뒀다.
- **그래프는 자주 안 붙는다.** 한국 기사에 차트로 옮길 만큼 깔끔한 수치가 드물어서다.
  ③은 같은 기준의 수치가 3개 이상일 때만 요청하고, ④는 숫자를 만들어 내거나 빠진 값을
  보간하는 것을 금지한다. 못 만들면 이유를 남기고 넘어간다 — **조작된 차트가 조작된 문장보다 위험하다.**

## API 키

첫 실행 때 ⚙︎ 설정이 열린다. [console.anthropic.com](https://console.anthropic.com/settings/keys) 에서
발급한 키를 넣으면 **이 기기의 localStorage** 에만 저장되고, 요청은 브라우저에서
`api.anthropic.com` 으로 바로 나간다(`anthropic-dangerous-direct-browser-access` 헤더 사용).

- 공용·공유 기기에서는 쓰지 말 것.
- 이 앱 전용 키를 하나 만들어 두면 필요할 때 폐기·재발급하기 쉽다.
- 초안·이력도 이 기기에만 저장된다. 저장소에 커밋되지 않는다.

## 모델과 비용

설정에서 모델을 고른다. 기본은 **Sonnet 5**.

| | Opus 5 · Sonnet 5 | Haiku 4.5 |
|---|---|---|
| `output_config.effort` | 지원 | **미지원** (보내면 400) |
| 웹검색·웹읽기 도구 | `_20260209` (동적 필터링) | `web_search_20250305` · `web_fetch_20250910` |
| 최대 출력 | 128K | 64K |

그래도 400이 오면 해당 옵션을 빼고 **자동 재시도**하며 그 모델을 기억한다
(`bw-no-effort`, `bw-basic-tools`) — 화면에는 오류가 보이지 않는다.

글 1편 비용은 Sonnet 5 기준 대략 **$0.4~0.6**(웹검색 $0.01×약 8회 + 토큰, 6단계 기준). 정보 탭이
응답의 `usage`를 공식 단가로 계산해 **실측값과 이번 달 누적**을 보여준다. 설정에서 월 한도를
정해 두면 초과 시 실행 전에 물어본다. 본문만 Opus 5로 올리는 토글도 있다.
